# P3 · 已有 Skill 复用

2026-11-19 调研快照，依据 PaperOrchestra 的 `d9bae99`。文中的仓库、CLI 和环境检查指调研当时的上游与本机环境。后续实测见[验收汇总](../validation.md)。

建议把 PaperOrchestra 做成一个可独立运行的 Skill。**默认用当前会话模型完成大纲、写作和审阅，沿用 PaperOrchestra 的阶段产物，按需接入 ARS、Zotero 和 PDF 工具。** 用户只需安装主 Skill 即可进入写作流程。生成 PDF 还需要运行环境能调用 LaTeX 工具链。ARS 适合复用写作、引文核验和审阅能力，作为可选依赖更稳妥。

原 CLI 无法通过更换模型名实现这条默认路线。大纲直接调用 Gemini，文献发现写死 `gemini-3-flash-preview` 并使用 Google Search，随后请求 Semantic Scholar 补元数据。文献综合也直接走 Gemini。OpenAI API 分支只覆盖经过通用模型路由的步骤，需要单独的 `OPENAI_API_KEY`。Python CLI 默认关闭绘图，仓库的 Bash 示例显式开启。 [CLI 参数](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/paper_writing_cli.py#L42) · [大纲调用](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/methods/agents/outline_agent.py#L38) · [文献检索与综合](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/methods/agents/literature_review_agent.py#L426) · [Bash 入口](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/paper_writing_cli.sh#L18) · [OpenAI 客户端](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/utils/openai_utils.py#L35)

## 安装、API 和再分发

- **默认依赖。** 主 Skill 可独立封装材料接收、阶段文件转换、引用键检查和编译入口。PDF 需要可用的 TeX 发行版和模板包，自动生成统计图才需要绘图库。原项目 README 指定 Python 3.11 和一组未锁版本的依赖，其中含原有模型 SDK、PDF 库和 Streamlit。直接封装原 CLI 会继承这些依赖。 [安装说明](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/README.md#L21) · [依赖清单](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/requirements.txt#L1)
- **可选安装与外部调用。** 本机 ARS 是 Codex 适配器 `0.1.27`，上游套件 `3.21.1` 锁定在 `127ff85e`。角色默认由当前会话执行，full-runtime 脚本生成计划 JSON。跨模型默认关闭，显式启用时才走所选通道。订阅式 Codex 通道仅用于限定的单条引文核验。程序化书目查询可能访问 Crossref、OpenAlex、Semantic Scholar、arXiv，这些是书目服务调用。Zotero 对接需要用户已有 Zotero Desktop 和启用本地 API。PaperBanana 上游另有 ClawHub Skill，仓库文档要求配置至少一个模型 API key，本次未验证其 Codex 兼容性。 ARS 版本清单（本机安装包 `skills/academic-research-suite/manifest.json:121`） · ARS 模型和书目路由（本机安装包 `skills/academic-research-suite/SKILL.md:139`） · Zotero 前置条件（本机安装包 `plugins/cache/openai-curated-remote/zotero/0.1.2/skills/zotero/SKILL.md:13`） · [PaperBanana 上游](https://github.com/dwzhu-pku/PaperBanana#quick-start)
- **可分发范围。** PaperOrchestra 主代码采用 Apache-2.0，分发时应保留许可、归属和适用的变更声明。会议模板要逐文件核对来源和条款，例如本地 `natbib.sty` 明示分发须附原始 `natbib.dtx`。若把 PyMuPDF/MuPDF 一并打包，还需核对其 AGPL 或商业许可。PaperBananaBench 数据卡标注 Apache-2.0，同时注明收录的论文图和方法文字版权归原作者。原仓库 README 也注明其生成数据集未随仓库提供。 [PaperOrchestra 许可](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/LICENSE#L90) · [natbib 声明](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/templates/iclr2025/natbib.sty#L11) · [PyMuPDF 许可](https://pymupdf.readthedocs.io/en/latest/about.html#license-and-copyright) · [PaperBananaBench 数据卡](https://huggingface.co/datasets/dwzhu/PaperBananaBench#license) · [PaperOrchestra 数据说明](https://github.com/google-research/paper-orchestra/blob/d9bae997e793a015ed38bb1605be9eb58c00284f/README.md#L48)
