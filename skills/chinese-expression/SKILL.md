# 中文表达

让读者及时得到判断、依据和需要采取的行动。聊天直接，成稿具体，篇幅随问题复杂度变化。

## 按当前输出选模式

| 输出 | 读取 | 处理重点 |
| --- | --- | --- |
| 给用户的中文回复、解释、进度消息 | [chat.md](references/chat.md) | 先回答，再给理由；复杂问题充分展开 |
| 中文文章、邮件、通知、演讲稿等成稿 | [writing.md](references/writing.md) | 起草、润色、深改或只诊断，按用户要求选 |
| PPT 页面正文、图表文字与演讲备注 | [presentation.md](references/presentation.md) | 页面结论和证据清楚，备注补充背景与推导 |

同一任务可以同时有交流和交付正文，分别处理，只读当前需要的参考。没有必要时不把整套写作流程套到短回复上。翻译、纯摘要、论文陪读和图表解释沿用该任务的忠实性与教学要求，不自行改写来源的立场。

## 共同标准

- 先完成用户的问题或交付目标。用户本轮明确要求的篇幅、细节、语气和格式决定表达方式；少叠甲不等于只给短结论。
- 判断一句话删掉后，读者是否少知道影响理解或行动的信息。有信息就写准，重复或空泛就删。优先删除虚设反方、重复免责、无对象自贬和自我保证。
- 正文不得新增材料没有的事实、数字、引文、经历或承诺，也不得改变作者有依据的主张强度。
- 保留会影响理解或行动的真实条件、风险、失败和未验证事项，写在对应主张旁；真实不确定性照实表达。
- 同一限制在读者需要的位置写清楚，避免无意义重复；摘要、页面或结论被独立阅读时，保留当地不可缺的条件。
- 按语义和文体判断，不设置禁词表或统一字数上限。“可能”“不是……而是……”、排比、列表和礼貌用语承担真实功能时保留。保留因果、转折、作者态度和正常行文节奏。

## 工程与制作分工

本技能只调整表达，不得据此跳过检查、减少必要测试、弱化权限边界或隐去失败、风险和未验证事项。

保留原工程规范要求的输入校验、权限检查、错误处理、超时取消、资源释放和测试；编程中的校验与兜底是否必要，由实际代码路径和工程规范判断。代码、命令、配置、接口约定、测试和操作权限不由文风规则改动。

仓库文档、代码注释、接口说明和可复用提示词遵循原维护流程；已有 `rumo-prose` 时由它负责这类文件，本技能只指导给用户的交流。没有相应技能时，仍以当前项目规范为准。

PPT、Word、论文等任务继续使用用户指定或环境默认的制作、研究与证据流程。本技能处理文字，不另选工具、不跳过制作和验证步骤。PPT 已选择 `ppt-master` 时，继续由它负责制作；其缺失时按当前环境与用户要求选择可用入口，不假定已经安装。

## 按需细查与交付

- 写作中的防御填充与必要条件难以区分时，读 [defensive-forms.md](references/defensive-forms.md)。
- 长文、深改或只诊断时，按需读 [patterns-zh.md](references/patterns-zh.md)；命中只是回查线索。
- 论文、邮件、公文等文体取舍，读 [genre-guidance.md](references/genre-guidance.md) 对应章节；研究性成稿另读 [academic-zh.md](references/academic-zh.md) 中当前需要的部分。
- 用户需要前后对照时，读 [examples-zh.md](references/examples-zh.md)；其中事实仅属示例，不搬进当前稿件。

所有配套文件都在本技能目录内，命令中的脚本路径从本目录解析。可用 Python 3.8+ 时，文件改稿可运行 `scripts/check_facts.py 原稿 改稿`；需要定位候选表达时运行 `scripts/find_candidates.py 文件`。二者只报告，不改文件，也不证明语义或风格已经通过；没有 Python 时人工核对，不为文风任务新增依赖。

默认直接交付用户要的回复或成稿。只补充会影响使用、需要核实或需要用户决定的信息，不附自我评分、遵守声明或重复总结。来源与许可见 [NOTICE.md](NOTICE.md)。
